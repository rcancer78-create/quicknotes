# ADR-011: виртуальный индекс открытых Markdown-задач

- Дата: 2026-09-12
- Статус: Accepted
- Реализовано в коде: да для Release 1.3 §9 пункты 1–6
- Пересмотр: при появлении наблюдаемого спроса на отдельную task-модель
- Связанные документы: [VISION.md](../../VISION.md), [ROADMAP.md](../../ROADMAP.md), [001-markdown-product-boundary.md](001-markdown-product-boundary.md)

## Контекст

ROADMAP §9 требует компактный виртуальный раздел «Задачи» по открытым checkbox в существующих заметках, без второго продукта и без отдельной сущности Task. Источник истины — `Note.Text`.

## Решение

- **Уже в коде.** `MarkdownTaskParser` индексирует только открытый checkbox: optional indent + `- [ ]` / `* [ ]` + обязательные пробел и непустой текст. Закрытые `[x]`/`[X]`, содержимое fenced code (`` ``` `` и `~~~`), escaped и inline-подобные строки не входят в индекс. Locator производим при чтении: `NoteId` / `Note.SyncId`, номер строки, нормализованный текст, optional due date, fingerprint. Таблицы Task нет; абсолютные диапазоны не сохраняются.
- **Дата.** Единственный documented token — `@YYYY-MM-DD`. Разбор строгий Gregorian `DateOnly.TryParseExact` + `CultureInfo.InvariantCulture`. Невозможные даты и похожие токены (`2026-10-01` без `@`, `@2026/10/01`, `@2026-10-1`, `user@2026-10-01`) датой не являются. Если в тексте несколько валидных токенов, берётся **первый** слева направо.
- **Индекс.** `TaskIndexService` сканирует незащищённые живые заметки батчами (64), с поиском и paging (50), `CancellationToken`. Защищённые заметки не раскрывают title/text/task и не попадают в plaintext-индекс. Порядок: due date (nulls last) → `UpdatedAt` desc → `NoteId` → line.
- **Навигация.** `MarkdownTaskNavigator` заново находит строку по fingerprint. Уникальный fingerprint после сдвига строк открывает ту же задачу. Locator несёт неперсистентный SHA-256 полного `Note.Text` на момент индексации (digest, без plaintext; не логируется). Если `SameFingerprintCount > 1`, exact-line разрешён только при совпадении этого snapshot proof с текущим текстом; после любого изменения snapshot — fallback, даже если такая же строка осталась на том же номере. Nearest line hint и `OccurrenceIndex` не доказывают идентичность. Иначе fallback: открыть заметку без selection/каретки на чужой checkbox и без утверждения точной навигации.
- **UI.** Виртуальный раздел «Задачи» в `VirtualSections` (не в дереве тегов и не в БД), визуально с акцентной полосой и подписью «виртуальный индекс». Список занимает центральную колонку. Выбор открывает исходную заметку и выделяет актуальную строку checkbox с прокруткой в видимую область.
- **Не является решением.** SMTP / email (§9.6, `[N]`), отдельная task-модель (`[D]`), plaintext-кэш на диске, индексирование разблокированных защищённых заметок. Windows toast — ADR-012.

## Альтернативы

- Таблица Task с line/offset — отвергнута ROADMAP как хрупкие якоря и дублирование данных.
- Индексировать `+ [ ]` как в предпросмотре — отвергнуто: контракт однозначен только для `-` и `*`.
- При дубликатах всегда брать первую строку — отвергнуто: молчаливый прыжок на чужой checkbox.

## Последствия

Новой схемы БД нет. CLI: `--tasks-index-smoke` → `artifacts/tasks-index-acceptance/`.
