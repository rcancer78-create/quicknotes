# QuickNotes — техническое задание на разработку с нуля

> Версия: 1.0-draft, 10 сентября 2026 года  
> Назначение: единый исходный документ для модели-разработчика, которая создаёт приложение с чистого листа.  
> Приоритет документа: продуктовые требования и критерии приёмки из этого ТЗ важнее деталей существующей реализации QuickNotes. Существующий код не является шаблоном архитектуры.

## 1. Задача

Создать законченное локальное Windows-приложение для быстрого захвата, организации, поиска и безопасного хранения текстовых знаний.

Главный пользовательский путь:

1. Пользователь выделяет текст в любом приложении.
2. Нажимает глобальную горячую клавишу.
3. QuickNotes надёжно получает выделение и открывает компактную форму захвата.
4. Пользователь при необходимости меняет заголовок, текст и теги и сохраняет заметку.
5. Позже он мгновенно находит заметку по заголовку, тексту, источнику или ветке тегов.
6. Данные сохраняются локально независимо от состояния сети, могут синхронизироваться между устройствами и могут быть восстановлены без установленного QuickNotes.

Короткая формула продукта: **«поймал → организовал → нашёл → не потерял»**.

## 2. Граница продукта

QuickNotes заменяет OneNote/Notion для быстрого текстового знания, но не пытается заменить Word, рисование, сложную вёрстку или PDF-редактор.

Входит в продукт:

- быстрый захват выделенного текста и OCR области экрана;
- самостоятельное создание и редактирование заметок;
- отдельные заголовки, Markdown-текст, теги, ссылки и вложения;
- быстрый полнотекстовый поиск и навигация по большой базе;
- история изменений, корзина и восстановление;
- защита отдельных заметок паролем;
- локальное сохранение, устойчивый журнал черновиков и опциональная S3-совместимая синхронизация;
- открытый переносимый экспорт и зашифрованный recovery-архив;
- импорт Markdown и HTML с предварительным просмотром;
- лёгкий раздел задач поверх Markdown-checkbox;
- светлая и тёмная темы, доступность, клавиатурная работа и корректный High DPI.

Не входит:

- HTML как основной формат заметки;
- WYSIWYG/WebView2, JS-редактор и браузерное хранилище;
- собственный формат документа, несовместимый с обычным текстом;
- email/SMTP-напоминания;
- совместное редактирование в реальном времени;
- сервер QuickNotes и обязательная учётная запись;
- мобильные и web-клиенты в первой версии;
- рисование, рукописный ввод, PDF-аннотации и сложная полиграфическая вёрстка;
- отдельная сущность Task: задачи извлекаются из Markdown-checkbox;
- прямой парсер закрытого формата OneNote.

## 3. Целевая платформа и поставка

- Windows 10 22H2 и Windows 11, x64.
- .NET 8 LTS, WPF, MVVM.
- Основной язык: C#; XAML только для представлений и ресурсов.
- SQLite с FTS5 для локальных данных.
- Приложение работает полностью офлайн, кроме явно включённой синхронизации.
- Поставка: подписанный self-contained x64 installer и переносимая сборка, если это не ослабляет защиту секретов.
- Обновление приложения никогда не мигрирует данные без предварительной проверенной резервной копии.
- Никакой телеметрии по умолчанию. Если она когда-либо появится, только opt-in и без содержимого заметок, заголовков, путей, URL и секретов.

## 4. Нефункциональные принципы

### 4.1. Local-first

- Локальный commit заметки не зависит от сети.
- Ошибка Sync не отменяет и не скрывает локальное сохранение.
- Все сетевые операции отменяемы, повторяемы и идемпотентны.
- UI различает состояния: «черновик», «сохранено локально», «ожидает отправки», «синхронизировано», «конфликт», «ошибка».

### 4.2. Сохранность данных

- Подтверждённое сохранение означает durable commit в SQLite и flush необходимых файлов.
- Запись БД, вложений, настроек, экспорта и архивов выполняется атомарно.
- Сбой процесса или питания не оставляет успешный результат частично опубликованным.
- Миграция схемы либо завершается полностью, либо исходные данные остаются восстанавливаемыми.
- Импорт и массовые операции имеют preview и транзакционный commit.
- Никакое автоматическое обслуживание не удаляет единственную копию пользовательских данных.

### 4.3. Конфиденциальность

- Защищённый текст, ключи и пароли не попадают в логи, аргументы командной строки, настройки, crash-report, облачные metadata и открытый экспорт.
- Секреты принимаются через защищённый UI или stdin для headless-инструмента.
- Пароли не сохраняются. Краткоживущие ключи хранятся только в памяти процесса и затираются при замене/выходе настолько, насколько это практически возможно в .NET.
- Защищённые заголовок, текст, история и вложения шифруются; plaintext-превью и поисковый индекс не сохраняются.
- Буфер обмена не используется для recovery key автоматически.
- DPAPI допустим для локальных cloud credentials, но не является единственным способом восстановления пользовательских данных.

### 4.4. Проверяемость

Каждое нормативное требование «должно/никогда» покрывается автоматическим тестом либо помечается в матрице релиза как ручная или внешняя проверка. Нельзя объявлять функцию готовой только по наличию кода.

## 5. Информационная модель

### 5.1. Note

Обязательные поля:

- `Id` — локальный технический идентификатор;
- `SyncId` — стабильный глобальный UUID;
- `Title` — отдельный заголовок, допускает пустое значение;
- `BodyMarkdown` — единственный источник истины содержимого;
- `CreatedUtc`, `UpdatedUtc`, `DeletedUtc?`;
- `SourceApplication`, `SourceWindowTitle`, `SourceUrl?`;
- `IsProtected` и версионированный crypto envelope;
- локальная ревизия и состояние публикации Sync.

Пустой заголовок не заменяется сохранённой выдуманной строкой. UI показывает локализованный fallback, например «Без заголовка».

### 5.2. Tags

- Иерархическое дерево произвольной глубины.
- Заметка может находиться в нескольких ветках.
- У тега есть стабильный `SyncId`, имя, родитель, порядок и набор синонимов.
- Автотеги определяются правилами с учётом Unicode, регистра, границ слова и технических токенов (`C#`, `.NET`, `foo-bar`).
- Ручные, автоматически найденные и явно подавленные теги различаются.
- Перемещение/объединение тегов не теряет связи и поддерживает preview.

### 5.3. Revisions

- Каждый подтверждённый смысловой commit создаёт неизменяемую ревизию.
- Ревизия содержит заголовок, тело, связи с тегами и crypto metadata соответствующего состояния.
- Смена пароля, protect/unprotect и разрешение конфликта тоже создают ревизию.
- Восстановление старой версии создаёт новую ревизию, а не переписывает историю.

### 5.4. Attachments

- Файл хранится под управляемым именем, отдельно от пользовательского имени.
- Метаданные: UUID, исходное имя, MIME/type hint, размер, SHA-256, даты.
- Вставка изображения из буфера: сохранение вложения и вставка Markdown-ссылки — одна логическая транзакция.
- Вложения защищённой заметки шифруются независимо AEAD-контейнером.
- Дедупликация по hash допустима только без утечки связей между защищёнными и открытыми данными.

### 5.5. Draft journal

- Черновик отделён от подтверждённой ревизии.
- Журнал обновляется не реже чем через 1 секунду после прекращения ввода и не блокирует UI.
- Для защищённой заметки журнал всегда зашифрован ключом текущей сессии.
- После crash/kill найденный черновик предлагается восстановить с датой и понятным сравнением.
- Журнал удаляется только после durable commit соответствующего содержимого.

## 6. Функциональные требования

### 6.1. Первый запуск

- Приложение сразу работоспособно без регистрации, облака и мастера из множества экранов.
- Короткий onboarding объясняет глобальный hotkey, расположение данных, backup и возможность Sync.
- Пользователь может пропустить Sync и recovery-настройку, но UI честно показывает незакрытый риск.
- Горячая клавиша по умолчанию выбирается безопасная и изменяемая; конфликт регистрации объясняется без аварии.

### 6.2. Быстрый захват

- Захват не уничтожает исходный clipboard: исходное значение и sequence восстанавливаются, только если пользователь не изменил clipboard во время операции.
- Поддерживаются Unicode, многострочный текст и разумный верхний предел размера.
- Пустое выделение, недоступный clipboard и приложение, не поддерживающее копирование, дают короткое понятное сообщение и возможность открыть пустую заметку.
- Повторное нажатие hotkey не создаёт гонку или дубликат окна.
- Форма захвата открывается не более чем за 300 мс p95 после получения текста.
- Фокус оказывается в заголовке или тексте согласно настройке; `Ctrl+Enter` сохраняет, `Esc` отменяет, `Tab` имеет предсказуемый порядок.

### 6.3. OCR

- Пользователь выбирает прямоугольную область экрана.
- Во время выбора окна QuickNotes не попадают в снимок.
- Результат открывается как редактируемый черновик и не сохраняется без подтверждения.
- Отмена, недоступный OCR language pack, пустой результат и ошибка распознавания не создают заметку.
- OCR не зависает при отсутствии WPF message pump и имеет ограниченные таймауты системных вызовов.

### 6.4. Редактор

- Режимы: редактирование, разделённый вид, просмотр.
- Markdown поддерживает заголовки, emphasis, strong, ссылки, code/blocks, списки, checkbox, цитаты, таблицы и изображения-вложения.
- Горячие клавиши форматирования работают над выделением без повреждения текста.
- Автопродолжение списков обратимо одним Backspace/Enter и не меняет уже сохранённый текст скрыто.
- Поиск внутри заметки: подсветка, следующий/предыдущий результат, счётчик.
- Оглавление и сворачивание секций вычисляются по Markdown и не меняют исходный текст.
- Закрытие с несохранёнными изменениями предлагает сохранить, не сохранять или остаться.
- Долгие операции не выполняются на UI thread; повторный запуск команды блокируется состоянием busy.

### 6.5. Поиск

- Основной поиск использует SQLite FTS5 и ищет по `Title` и `BodyMarkdown`.
- Поддерживаются фильтр по ветке тегов, пересечение нескольких тегов, источник, диапазон дат, наличие вложений, состояние защиты и корзина.
- Совпадения подсвечиваются в карточке и редакторе.
- Поиск выполняется по мере ввода с debounce и отменяет устаревший запрос.
- Пагинация/виртуализация выполняются на уровне запроса; весь результат и все ViewModel не материализуются заранее.
- Защищённая заблокированная заметка не индексируется и не раскрывается сниппетом. После unlock допустим только временный поиск в памяти в рамках явной сессии.
- При недоступности FTS приложение сообщает о fallback и сохраняет корректность результата.

### 6.6. История и корзина

- История показывает дату, устройство/источник изменения и diff заголовка/текста.
- Удаление переносит в корзину (tombstone для Sync).
- Восстановление из корзины не теряет историю и связи.
- Окончательная очистка требует подтверждения, показывает объём и не выполняется при неопределённом состоянии Sync без явного выбора пользователя.

### 6.7. Защита заметки

- AES-256-GCM; случайные salt и nonce; версионированный envelope и KDF-параметры рядом с ciphertext.
- KDF выбирается после benchmark и security review. Предпочтительно Argon2id; если используется PBKDF2-HMAC-SHA256, его стоимость измеряется на целевой машине и не задаётся «на глаз».
- Reader использует параметры envelope и сохраняет обратную совместимость.
- Неверный пароль, tamper и неизвестная версия завершаются fail-closed без изменения данных.
- Protect, смена пароля и unprotect атомарно охватывают заголовок, тело, историю и вложения.
- До включения защиты пользователь видит однозначное предупреждение: recovery key архива не заменяет пароль отдельной заметки.
- Подсказка пароля не должна раскрывать пароль и не шифруется как секрет.

### 6.8. Открытый экспорт

- Экспортируются только незашифрованные неудалённые заметки.
- Формат: UTF-8 Markdown + YAML front matter, обычные вложения и `manifest.json`.
- Manifest содержит format/version, UTC, число сущностей, пропуски, ошибки и SHA-256 файлов.
- Пользователь выбирает каталог и подтверждает, что создаётся plaintext-копия.
- Snapshot строится в принадлежащем операции staging и публикуется атомарно.
- Неудача сохраняет предыдущий успешный snapshot.
- UI показывает путь, время и полноту только последнего успешного экспорта.
- Результат читается Проводником и Блокнотом без QuickNotes.

### 6.9. Зашифрованный recovery-архив

- Версионируемый бинарный контейнер включает согласованный snapshot SQLite и все вложения как они лежат на диске, не расшифровывая защищённые заметки.
- Payload шифруется отдельным случайным DEK через AEAD.
- DEK имеет два независимых wrap: пароль архива и recovery key.
- Canonical header целиком аутентифицирован; неизвестные format/KDF отвергаются.
- До KDF проверяются лимиты размера, количества записей, salt и стоимости, чтобы недоверенный файл не вызвал DoS.
- Внутренний формат запрещает traversal, absolute/UNC/ADS, reparse traversal, overwrite и zip-bomb-подобные декларации.
- Create не перезаписывает существующий архив и публикует новый файл атомарно.
- Dry-run проверяет AEAD, manifest, пути, размеры и checksums без единой записи назначения.
- Restore пишет только в отсутствующий или пустой новый каталог через staging; проверяет SQLite integrity и миграции до публикации.
- Восстановление in-place живого профиля запрещено.
- Headless CLI принимает секрет только через stdin, не запускает WPF/onboarding/Sync и возвращает документированные exit codes.

### 6.10. Recovery key

- 256-битный CSPRNG-ключ, представленный устойчивой к ошибкам кодировкой группами и с checksum.
- Показывается один раз после создания архива и обязательного успешного recovery dry-run.
- Файловая копия создаётся только по выбранному пользователем пути, новым файлом без overwrite, атомарно и по умолчанию не рядом с архивом.
- Печатная копия содержит назначение, checksum, archive ID и предупреждение, что ключ не заменяет пароль защищённой заметки.
- Нет автоматического clipboard, логирования, settings/DB/DPAPI persistence.
- Ротация меняет только recovery wrap: payload ciphertext и password wrap остаются byte-for-byte прежними.
- Новый ключ проверяется до атомарной публикации; старый после успеха не открывает архив; при сбое исходный файл byte-for-byte неизменен.

### 6.11. Синхронизация

- S3-compatible transport, первым поддерживаемым сервисом является Yandex Object Storage.
- Credentials — минимальные права отдельного бакета, локально защищены DPAPI.
- Sync шифрует контент до сети. Object key, metadata, body и лог не раскрывают заголовок, текст, теги, имена вложений и пароли.
- У каждого изменения есть стабильный id; повтор upload/download не создаёт дубликаты.
- Используются ETag/precondition и явная обработка гонок.
- Tombstone не исчезает до подтверждения, что его увидели требуемые устройства/политика retention.
- Конфликт никогда не разрешается молча по wall-clock времени.
- Варианты: Keep Local, Keep Remote, Keep Both, ручное объединение. Решение создаёт новую ревизию.
- Смена sync-пароля/параметров KDF обратимо читает старые конверты и не оставляет смешанное неопределённое состояние.
- Scheduler использует backoff+jitter, реагирует на offline/online и не будит систему частыми циклами.
- Quota, corrupt object, access denied и network timeout различаются в статусе.

### 6.12. Импорт и сборка заметок

- Импорт Markdown и HTML; Word/OneNote — через документированный экспорт в один из этих форматов.
- Перед commit показываются структура, mapping «блокнот/каталог → корневой тег», неподдержанные элементы, потери и дубликаты.
- Импорт транзакционный, отменяемый до commit и детерминированно повторяемый.
- Дедупликация предлагает решение, но не объединяет разные заметки автоматически.
- Несколько быстрых заметок можно собрать в одну: пользователь задаёт порядок, разделители, заголовок и судьбу исходников; по умолчанию исходники сохраняются.

### 6.13. Задачи и уведомления

- Виртуальный раздел индексирует открытые `- [ ]` в Markdown.
- Поддерживается дата `@YYYY-MM-DD` с фиксированным parser contract.
- Переход открывает исходную заметку и checkbox.
- Закрытие задачи изменяет исходный Markdown одной транзакцией и создаёт ревизию.
- Локальные Windows-уведомления не раскрывают текст защищённой заметки без отдельного opt-in.

## 7. UI/UX — обязательная концепция

### 7.1. Характер интерфейса

Интерфейс современный, спокойный, быстрый и информационно плотный. Он не имитирует мобильное приложение на настольном экране: нет гигантских заголовков, пустых hero-блоков, чрезмерных карточек и широких кнопок при малом количестве действий.

Визуальные ориентиры:

- нейтральная поверхность, один спокойный accent color;
- системный Segoe UI Variable/Segoe UI;
- базовый шаг сетки 4 DIP; основные интервалы 8/12/16/24 DIP;
- радиусы 6–8 DIP, тонкие границы, тени только для визуального слоя над другим;
- обычная высота control 32–36 DIP, compact toolbar 36–40 DIP;
- минимум постоянного текста; подробности — tooltip, secondary text или contextual panel;
- цвет не является единственным носителем статуса.

### 7.2. Главное окно

Трёхпанельное рабочее пространство:

1. **Навигация, 200–280 DIP:** Inbox/Все заметки/Избранное/Задачи/Корзина, дерево тегов со счётчиками, Sync status внизу.
2. **Список, 280–420 DIP:** единая строка поиска и фильтров, виртуализированные карточки, сортировка.
3. **Содержимое, остальное пространство:** заголовок, metadata/status bar, Markdown editor/preview, вложения и история.

Требования:

- панели изменяемы splitter-ами, размеры сохраняются в допустимых границах;
- при ширине ниже 900 DIP навигация становится выезжающей, список и редактор работают как master/detail;
- ни один toolbar не переносится хаотично: вторичные действия уходят в overflow;
- пустое состояние объясняет следующий шаг и содержит одну главную кнопку;
- выбранный объект, hover и keyboard focus визуально различимы;
- scroll position, выбранный тег и ширины панелей восстанавливаются, но не ценой зависания старта.

### 7.3. Карточка заметки

- Заголовок: одна строка, fallback «Без заголовка» только визуально.
- Сниппет: максимум 2–3 строки с подсветкой поиска.
- Компактная строка: время, до трёх тегов `+N`, источник, attachment/protected/task indicators.
- Статус Sync — маленький icon+tooltip; ошибки доступны для клавиатуры и не маскируются цветом.
- Карточка не меняет высоту самопроизвольно при выделении.

### 7.4. Быстрый захват

- Отдельное небольшое окно примерно 560×420 DIP, запоминающее разумный размер.
- Заголовок, текст, строка тегов, metadata источника и две основные команды: сохранить/отменить.
- Не дублирует всю навигацию главного окна.
- После сохранения показывает ненавязчивое подтверждение и закрывается согласно настройке.

### 7.5. Редактор и preview

- Заголовок не выглядит как отдельная тяжёлая форма; это первая строка документа с ясным focus state.
- Formatting toolbar появляется компактно и доступен клавиатурой.
- Split preview сохраняет позицию прокрутки логически по секции, а не только по пикселям.
- Protected lock-state полностью заменяет содержимое безопасной заглушкой; не оставляет старый plaintext на экране.
- Сохранение, draft recovery, конфликт и ошибка показываются рядом с документом, не только глобальным toast.

### 7.6. Поиск и фильтры

- `Ctrl+K`/`Ctrl+F` фокусирует глобальный поиск; `Esc` сначала очищает transient filter, затем возвращает фокус.
- Активные фильтры представлены компактными removable chips и доступны screen reader.
- Продвинутые фильтры открываются popover, а не занимают постоянную вертикальную полосу.
- Нулевой результат различает «в базе нет совпадений» и «совпадения скрыты фильтрами».

### 7.7. Настройки

Категории: General, Capture, Editor, Appearance, Data & Backup, Sync, Security, Accessibility, About.

- Поиск по настройкам.
- Изменения применяются предсказуемо: instant для визуальных параметров, явное Save/Test для внешних подключений.
- Опасные действия отделены и требуют точного подтверждения.
- Пароли очищаются после операции; сохранённые credentials показываются как факт наличия, а не маска реального значения.
- Экран Backup всегда показывает последний подтверждённый открытый экспорт и encrypted archive, их путь/дату/полноту и незакрытые риски.

### 7.8. Диалоги и обратная связь

- Не использовать modal dialog для обычного успеха.
- Опасный dialog называет действие, объект и последствия; default focus — безопасная кнопка.
- Toast не является единственным местом ошибки: проблема остаётся доступной в соответствующем экране.
- Progress determinate, когда объём известен; иначе показывается этап операции.
- Cancel означает реальную попытку отмены. После точки commit UI сообщает «завершаем», а не обещает невозможную отмену.

### 7.9. Темы, DPI и доступность

- Light, Dark, System без перезапуска.
- Все цвета — semantic resources; никаких случайных hardcoded RGB в view.
- Контраст WCAG AA для текста и интерактивных элементов.
- 100/125/150/200% DPI, корректное поведение при переносе между мониторами.
- Полная работа клавиатурой, видимый focus, логичный tab order, access keys.
- AutomationProperties Name/HelpText для icon-only controls; screen reader объявляет статусы и ошибки.
- Reduce motion учитывается; анимации 120–180 мс и не блокируют ввод.
- Минимальная hit target 28×28 DIP в compact UI, 32×32 предпочтительно.

## 8. Архитектура с чистого листа

### 8.1. Структура solution

- `QuickNotes.Domain` — сущности, value objects, инварианты; без WPF/EF/AWS.
- `QuickNotes.Application` — use cases, интерфейсы портов, команды/запросы, транзакционные границы.
- `QuickNotes.Infrastructure` — SQLite/EF Core, файлы, crypto, S3 transport, Windows adapters.
- `QuickNotes.Presentation.Wpf` — views, ViewModels, navigation, themes, composition root.
- `QuickNotes.RecoveryCli` — независимый console entry point восстановления и диагностики архивов.
- `QuickNotes.Tools` — benchmark и dev-only generators; не часть UI.
- отдельные unit, integration, architecture, UI contract и end-to-end test projects.

### 8.2. Правила зависимостей

- Domain не зависит от внешних библиотек приложения.
- Application зависит только от Domain и абстракций.
- Infrastructure реализует порты; Presentation вызывает use cases, а не DbContext/SDK напрямую.
- Единственный composition root находится при старте WPF/CLI.
- ViewModel не создаёт production services и не выполняет SQL/crypto/network.
- ViewModel делятся по feature; запрещён «главный» класс на тысячи строк и десятки зависимостей.
- Все долгие API принимают `CancellationToken`; library-код не использует `async void`, `.Wait()`, `.Result`.

### 8.3. Транзакции и конкуренция

- Один координатор mutation на профиль сериализует несовместимые операции: migrations, restore, import, protect/unprotect, archive snapshot.
- UI читает immutable snapshots/DTO и применяет optimistic concurrency по revision.
- Файлы публикуются через temp/staging, принадлежащие конкретной операции; запрещена очистка по широким маскам.
- Recovery после crash опирается на journal/manifest операции, а не на угадывание по имени файла.

### 8.4. Миграции

- Каждая версия схемы — отдельная идемпотентная миграция с pre/postcondition.
- Поддерживается upgrade с каждой выпущенной версии на заполненной базе.
- Перед первым изменением создаётся проверенный backup.
- Частично применённая миграция безопасно повторяется или восстанавливается.
- `user_version` выше поддерживаемой версии открывается read-only с понятным сообщением, не «понижается».

### 8.5. Логи

- Structured local log с уровнями и correlation id операции.
- Allowlist полей вместо попытки вычистить секреты после формирования строки.
- Нет body/title/password/key/clipboard/URL query/полных пользовательских путей.
- Ротация по размеру и срок хранения; экспорт диагностики показывает пользователю состав до создания файла.

## 9. Производительность

На эталонном наборе 10 000 заметок, реалистичном дереве тегов, истории и 500 МБ вложений:

- cold start до готовности ввода: p95 ≤ 1,5 с;
- поиск по мере ввода: p95 ≤ 150 мс;
- открытие редактора: p95 ≤ 300 мс;
- быстрый capture после получения текста: p95 ≤ 300 мс;
- прокрутка списка: ≥ 50 fps;
- память в покое: ≤ 400 МБ;
- сохранение обычной заметки: p95 ≤ 100 мс без учёта Sync.

Методика, железо и генератор набора фиксируются в репозитории. Изменение цели возможно только через ADR с измерениями.

## 10. Тестовая стратегия

### 10.1. На каждый commit

- Release build с analyzers и warnings as errors;
- unit и integration tests;
- миграции со всех поддерживаемых версий;
- crypto known-answer/roundtrip/tamper/limits;
- format/architecture checks;
- timeout/hang protection и TRX только как CI artifact.

### 10.2. Перед каждым релизом

- полный suite минимум три раза на чистых процессах;
- clean-machine install, upgrade и uninstall без удаления данных;
- восстановление открытого экспорта без QuickNotes;
- `.qnar` restore через recovery key под отдельным Windows SID в новый каталог;
- реальный Yandex Object Storage smoke на отдельном тестовом бакете и двух изолированных профилях;
- UI-матрица Light/Dark, narrow/normal, 100–200% DPI, keyboard и screen reader;
- crash/kill во время draft, save, migration, import, archive, rotation и Sync;
- `git diff --check`, отсутствие secrets и воспроизводимость сборки.

### 10.3. Обязательные security-негативы

- wrong password/key, mutated header/tag/ciphertext/tail;
- неизвестная версия/алгоритм и завышенные KDF/size/count до дорогой работы;
- traversal/absolute/UNC/ADS/reparse/overwrite;
- failure injection до и после staging/publish;
- старый recovery key после rotation;
- protected plaintext отсутствует в FTS, logs, export, Sync metadata и temp;
- CLI не эхо-секрет и не принимает его через argv.

## 11. Этапы создания

Каждый этап заканчивается работающим инкрементом, приёмкой и commit. Нельзя начинать следующий этап с красными обязательными gates.

### Этап A — фундамент

- solution layering, CI, analyzers, style;
- SQLite schema/migrations, atomic settings/files, logging;
- базовые Note/Tag/Revision/Attachment;
- главное окно, темы, навигация, виртуализированный список;
- green build/tests и установочный smoke.

### Этап B — основная ценность

- hotkey/clipboard capture, compact capture window;
- editor, title, Markdown preview, draft journal;
- tags/autotags, FTS/search/filters, history/trash;
- OCR;
- performance dataset и базовые цели.

### Этап C — защита и переносимость

- note protection после отдельного threat model;
- open export;
- encrypted archive, CLI, recovery key/offline copy/rotation;
- isolated-SID restore и failure-injection acceptance.

### Этап D — Sync

- encrypted S3 envelopes/blobs, queue, scheduler;
- conflict detection/resolution, quota/cleanup, password rotation;
- реальный Yandex smoke на двух профилях.

### Этап E — страницы и перенос

- полнофункциональный Markdown UX, outline, tables, images;
- HTML/Markdown import и merge-notes preview;
- polished conflict comparison.

### Этап F — ежедневный ритм и выпуск 1.0

- virtual Tasks + Windows notifications;
- accessibility/DPI/performance polish;
- semantic-search: ADR-005 B — feature removed; FTS remains;
- installer/update/backup restore rehearsal, user documentation, release matrix.

## 12. Definition of Done функции

Функция готова только если:

1. Требования и нештатные состояния определены.
2. Архитектурная граница соблюдена; нет скрытого service construction в UI.
3. Есть unit/integration tests и, где нужно, UI/e2e/manual evidence.
4. Есть cancellation, re-entry protection и понятный progress/error UX.
5. Проверены data-loss, privacy и backward-compatibility последствия.
6. Release build без предупреждений и весь suite зелёный.
7. Документация/ADR обновлены вместе с кодом.
8. Для network/crypto утверждений есть проверка на реальном или изолированном окружении, а не только fake.

## 13. Критерии итоговой приёмки продукта

Продукт можно назвать законченным, когда одновременно выполнено следующее:

- чистая машина устанавливает и запускает QuickNotes без ручной настройки runtime;
- новый пользователь создаёт первую заметку через hotkey менее чем за минуту;
- kill во время редактирования не теряет восстановимый черновик;
- локальное сохранение работает при полном отсутствии сети;
- поиск и прокрутка выполняют численные цели на 10 000 заметок;
- protected note не оставляет обнаружимого plaintext в постоянных хранилищах продукта;
- открытый export читается стандартными средствами Windows;
- encrypted archive восстанавливается recovery key под другим Windows SID без DPAPI исходного профиля;
- два изолированных клиента проходят полный реальный Sync-сценарий, включая конфликт и вложение;
- UI пройден в Light/Dark, 100/125/150/200% DPI, узкой/обычной ширине, клавиатурой и screen reader;
- upgrade с каждой выпущенной схемы сохраняет данные, downgrade не портит их;
- installer/update failure оставляет предыдущую рабочую версию и данные;
- документация не обещает ни одной гарантии, для которой нет теста или явно указанной ручной проверки.

## 14. Инструкции модели-разработчику

- Считать этот документ требованиями к новому проекту, а не заданием рефакторинга старого.
- До кода создать `ARCHITECTURE.md`, threat model, schema draft, UI navigation map, wireframes ключевых состояний и план тестов.
- Реализовывать вертикальными срезами; после каждого среза оставлять сборку запускаемой.
- Не копировать существующий крупный `MainViewModel`, размытый composition root или синхронные async-мосты.
- Не добавлять библиотеку/фреймворк без объяснения стоимости, лицензии, размера поставки и новой security boundary.
- Не сокращать критические требования ради демонстрации happy path.
- Не использовать mock/fake как единственное доказательство Sync, crypto recovery, installer или UI.
- Не менять формат, crypto envelope или migration без versioning и backward-read tests.
- Не выполнять destructive cleanup по glob/маске; удалять только ресурс, созданный известной операцией.
- Не коммитить секреты, пользовательские данные, базы, логи, build/test output.
- В каждом отчёте разделять: реализовано; проверено автоматически; проверено вручную; требует внешнего окружения; отложено.

Итог работы модели — не набор файлов и не зелёный happy-path test, а устанавливаемое приложение, которое проходит матрицу итоговой приёмки и безопасно переживает сбой, потерю профиля и конфликт синхронизации.
